# Osler Forecast API Contract

Contract version: `osler.forecast.v1`  
Model version: `patient-state-precision-20260813`

This is the frozen frontend contract for the retrospective Osler demo. It is
research-only factual forecasting: it does not diagnose, estimate causal
treatment effects, recommend treatment, or prescribe. The forecast API is
isolated from the drug-ranking pipeline. Calling any endpoint in this document
must not change the request or result of `/api/analyze`, including candidate
order or score.

## Common rules

- JSON is used for every request and response.
- `schema_version` is `osler.forecast.v1`, except the monitoring case document,
  whose own `schema_version` is `osler.monitoring-cases.v1`.
- `model_version`, `case_source`, and `safety_boundary` must be displayed or
  retained as provenance; clients must not infer a clinical claim from them.
- `forecasts[].population.point` is the population point estimate.
- `forecasts[].personalized.point` is the patient-state-adjusted point estimate.
  Its `delta_vs_population` is descriptive model output, not a causal effect.
- Only `tier: "validated_artifact"` may display numeric `lower` and `upper`.
  A client must hide interval UI for every other tier, even if an unknown future
  server version accidentally supplies values.
- `belief_states` are illustrative internal patient state. They are not measured
  hidden physiology and must not be shown as diagnosis.
- Allowed replay signals are only `stable`, `watch`, and `research_signal`.
  They are demo presentation states, not clinical alerts or thresholds.
- Calibrated coverage is target-specific artifact metadata, not a global 90%
  constant. In particular, `creatinine@24h` retains its exact target coverage
  of `0.89`; clients must display the returned value without coercing it to 90%.
- `physical_domain` and `note` are machine-readable target metadata. For urine
  output the physiological support begins at zero, but the raw calibrated
  statistical interval is returned unchanged and may extend below that support.
  It must not be clamped or clinically interpreted.

### Tier semantics

| `tier` | Point values | Interval | Meaning |
| --- | --- | --- | --- |
| `validated_artifact` | Population and personalized | Numeric `lower`/`upper` from the exact serialized conformal artifact | One of exactly 12 authorized target x horizon cells |
| `illustrative` | May contain illustrative/persistence point output | `lower: null`, `upper: null` | Research illustration without an exact validated interval artifact |
| `unsupported` | `population: null`, `personalized: null` | `lower: null`, `upper: null` | Fail-closed abstention for an unavailable target x horizon |

## `POST /api/forecast`

Build a factual forecast from the observations visible at the replay anchor.

### Request

| Field | Required | Type | Contract |
| --- | --- | --- | --- |
| `trajectory` | yes | non-empty array of objects | Time-ordered observation prefix. Each row needs numeric `hours_since_onset`. Future/outcome fields are rejected. |
| `anchor_hour` | replay: yes | number | Must equal `trajectory[-1].hours_since_onset`. No row may occur after it. |
| `patient_id` | no | string | Demo identifier; it is not persisted by this API. |
| `case_source` | no | non-empty string | Provenance label; defaults to `user_supplied`. Use the monitoring case value unchanged during replay. |
| `requested_cells` | no | array of objects | Each object is `{ "target": string, "horizon_hours": number }`. Omit to request the runtime's full display set. Unknown cells return `tier: "unsupported"`; they do not silently fall back. |

For a retrospective case, the frontend may receive the complete timeline from
`GET /api/monitoring/cases` for playback. It must send only
`observation_events.slice(0, visible_count).map(event => event.observation)` to
this endpoint. The anchor is the final row's time. Sending a later row with an
earlier anchor is a `400` error. This is the future-leakage boundary.

### Response

The response contains:

- `patient_id`, `model_version`, `case_source`, `latest_hour`, `input_rows`, and
  `schema_version`.
- `forecasts`: one result per requested/display cell. Each result has `system`,
  `target`, `horizon_hours`, `status`, `tier`, `population`, `personalized`,
  `lower`, `upper`, `interval_status`, and `can_personalize`. Validated results
  also carry `interval_target_coverage`; unsupported results carry `reason`.
- `belief_states`: illustrative internal state grouped by body system.
- `contract`: serialized-cell list and interval fail-closed policy.
- `safety_boundary`: all clinical, diagnostic, causal, counterfactual,
  treatment, prescribing, and drug-ranking permissions are `false`.

## `GET /api/forecast/capabilities`

Returns the stable discovery document. Important fields are `schema_version`,
`model_version`, `systems`, `display_cells`, `serialized_precision_cells`,
`safety_boundary`, `request_schema`, `response_tiers`, and `replay_policy`.
`replay_policy.request_uses_trajectory_prefix_only` and
`replay_policy.anchor_equals_prefix_last_observation` are both `true`;
`live_monitoring_supported` and `clinical_alerts_supported` are both `false`.

## `GET /api/forecast/validation-summary`

Returns `serialized_validated_artifact_count` (exactly 12), per-cell artifact and
gate metadata, `interval_width_reduction`, `model_version`, `schema_version`, and
`safety_boundary`.

`interval_width_reduction.scope` is
`held_out_cohort_aggregate_only`. The range (approximately 1.1%-34.5% across 120
held-out runs; median approximately 11.8%) is an aggregate retrospective
validation result. It is not a case-level, current-anchor, or real-time interval
shrinkage measurement. The UI must never attach it to an individual forecast.

## `GET /api/health/models`

Strictly verifies and loads all 12 serialized artifacts against the release
manifest, then runs a deterministic canonical-sample prediction through
preprocessing, each sklearn population anchor, each neural model forward, and
the conformal interval calculation. The response separates `integrity_load`
from `inference_smoke`; each has its own `status`, `ready`, counts, and checks.

- `200`: `ready: true`, all 12 artifacts loaded and all 12 validated cells
  produced finite points with ordered finite interval bounds.
- `503`: `ready: false`, at least one integrity or inference check failed. This
  includes preprocessing, sklearn/joblib prediction, or model-forward failure.
  The frontend must show
  an unavailable/degraded state and must not present stale forecast values as a
  successful model response.

The committed fixture includes a deterministic fixture-only `503` example; it
does not mutate or corrupt a real artifact.

## `GET /api/monitoring/cases`

Returns `schema_version`, `model_version`, top-level `safety_boundary`, and
`cases`. The included eICU CRD Demo 2.0.1 stay is `eicu-demo-2677807`.

Each case contains backend-supplied `display_name`, provenance, non-diagnostic context, `replay_metadata`, and
the full ordered `observation_events` timeline. `replay_metadata` fixes:

- `retrospective: true` and `not_live: true`;
- `initial_visible_count` and a one-observation `next_observation` step;
- `forecast_request_policy: "trajectory_prefix_only"`;
- units for every observation variable; and
- `forecast_observation_matching.supported: false`.

Each event contains `event_id`, `available_at_hour`, `signal`, and `observation`.
`available_at_hour` equals `observation.hours_since_onset`, and event times are
strictly increasing. Forecast-vs-observation matching is deliberately not
implemented: no observation is treated as truth for a forecast without an
explicit `due_hour`, `target`, `horizon`, and tolerance contract, and no clinical
accuracy claim is made.

## HTTP and error behavior

| Status | Meaning |
| --- | --- |
| `200` | Successful endpoint response. Unsupported forecast cells still use `200` with explicit `tier: "unsupported"` abstention. |
| `400` | Invalid/missing JSON object, empty or malformed trajectory, non-monotonic time, anchor mismatch/future row, forbidden future/outcome field, invalid requested cell, or invalid `case_source`. Body is `{ "error": "..." }`. |
| `503` | Strict model health is degraded; applies to `/api/health/models`. |
| `500` | Unhandled server fault. It is not a forecast result and must not be rendered as one. |

## Deterministic frontend fixtures

`demo/forecast_api_fixtures.json` contains:

- the monitoring case response;
- first-prefix, second-prefix, and third-prefix forecast request/response pairs;
- the validation summary;
- a deterministic fixture-only unhealthy model response; and
- an unsupported-cell request/response pair.

Regenerate it with:

```powershell
python -m demo.build_forecast_api_fixtures --write
```

The browser loads this exact document from `GET /api/forecast/fixtures` only
after an explicit user action. It is always labelled “Cached research
demonstration” and is never substituted automatically.

`test_forecast_api_fixtures.py` rebuilds the document through the live Python
contract and requires exact equality, preventing fixture/API drift.
